# 0007: データベースにMySQL 8.4を採用する

- 状態: 採用
- 決定日: 2026-10-02

## 状況

Pastbuzzの開発・CI環境ではMariaDBの異なるバージョンを使用していました。本番候補としてGCPとAWSのマネージドDBを検討するにあたり、ローカル、CI、本番のデータベースエンジンを揃える必要があります。

## 決定

データベースエンジンにMySQL 8.4を採用します。RailsのActive Record接続には既存のTrilogyアダプタを使い、開発環境とCIもMySQL 8.4で統一します。

## 理由

- MySQL 8.4はLTS系列であり、新規環境で長期運用しやすい
- GCP Cloud SQL for MySQLとAmazon RDS for MySQLの両方で利用でき、クラウド選択の自由度を保てる
- 開発、CI、本番のエンジン差を減らし、DB固有の不具合を早期に検出できる
- 現在のTrilogyアダプタを継続利用できる

## 影響

- 開発環境のMariaDB用Composeサービスと永続ボリュームは新しいMySQL用構成に置き換わります。既存のMariaDBボリュームは自動移行・削除されないため、必要なデータがある場合は別途移行します。
- MySQLのマイナーバージョンはクラウドプロバイダーの提供状況と保守方針に従い、定期的に更新します。
- Trilogyを含むRailsアプリケーションの接続、migration、テストをMySQL 8.4で検証します。
